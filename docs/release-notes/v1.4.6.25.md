# v1.4.6.25

本版本重点修复混合下载目录批量刮削时的图片串片和失败后错误归档问题。

- 不同番号使用独立的 NFO、poster、fanart 暂存目录，避免前后任务交叉覆盖图片。
- 详情与缓存严格校验番号，前端忽略旧搜索批次迟到的详情响应。
- 使用 JAV321 精确检索并按图片分辨率自动择优，改善低清封面和 fanart。
- NFO、poster、fanart 任一缺失或无效时，任务明确标记失败，跳过规整归档并保留源视频。
- 移动模式先完整落地和校验归档产物，成功后才删除源视频；缺件时回滚本次目标文件。
- 修复局域网 HTTP 或剪贴板权限受限时磁链无法复制的问题，增加主要浏览器兼容复制与完整链接手动兜底。
- 演员头像新增“在每部影片目录保留 actors 文件夹”开关；关闭后继续使用全局本地缓存完成头像刮削、NFO 回写和 Emby 主图同步。
- 独立演员头像任务新增“强制重扫设定目录”：遍历目录内全部 NFO，忽略以前写入的头像 URL 与缓存，按番号重新查询并覆盖错误头像、NFO 和 Emby 主图。
- “立即扫描”改为先保存当前页面设置，再扫描实际保存的下载/工作目录；手动与后台扫描互斥，并清空旧的“最近处理”和进程内旧路径记忆，避免目录删除重建后仍显示或跳过旧文件。
- 修复任务按番号聚合导致同番号其他文件覆盖失败状态的问题；任务现按源文件独立保存，并支持按番号、文件名、路径或错误信息搜索。
- 修复失败任务的“当前阶段”仍显示绿色“已完成”的状态矛盾；失败时现在明确显示“失败”，因刮削失败未执行归档时归档结果显示“跳过”。
- 修复搜索卡片的封面偶尔从有图变成无图：图片代理校验真实图片字节并自动清除历史误缓存的 HTML/验证页；大图和缩略图遇到瞬时网络失败时各自动重试一次。
- 修复刮削元数据带有失效封面 URL 时不会进入 JavDB 兜底的问题：现在以实际可下载、可解析的图片字节判定封面成功；失败后优先通过已启用的 JavDB 过盾搜索和详情页按番号恢复封面，再尝试其他来源。
- 修复 JAV321 偶尔把“JAV321 dmm”等来源占位词作为影片标题，导致错误跳过日文翻译的问题；只对明确的占位标题按番号使用 JavDB/JavBus 校正，并补齐缺失详情后再执行翻译。
